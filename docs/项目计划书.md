# AI小说转剧本工具 - 项目计划书

## 一、项目概述

### 1.1 项目背景

很多小说作者希望将自己的作品改编成剧本，但剧本创作门槛较高，需要掌握专业的格式和技巧。本项目旨在开发一款AI辅助剧本创作工具，通过大模型自动将小说文本转换为结构化剧本，降低改编门槛，提升创作效率。

### 1.2 项目目标

开发一款Web应用，能够：
- 接收3个章节以上的小说文本（支持txt、md、docx格式）
- 自动识别章节结构
- 调用AI大模型将小说转换为结构化剧本
- 输出符合规范的YAML格式剧本
- 支持在线预览和下载

### 1.3 项目信息

| 项目名称 | AI小说转剧本工具 |
|---------|----------------|
| 项目代号 | Novel2Script |
| 版本号 | v1.0.0 |
| 开发周期 | 3天 |
| 目标用户 | 小说作者、编剧、内容创作者 |

## 四、数据库设计

### 4.1 设计原则

1. **只存储文件路径**：不存储文件内容，需要时读取文件路径再获取内容
2. **减少数据库压力**：避免大文本字段影响查询性能
3. **文件系统更适合**：大文件存储在文件系统中，数据库只存元数据

## 五、YAML Schema 设计

### 5.1 设计原则

1. **剧本格式标准化**：遵循中国影视剧本行业规范
2. **内容连贯性**：场景描写和对话保持自然流畅，不碎片化
3. **行文表现力**：通过文字描写体现镜头调度，不使用技术指令
4. **易于阅读编辑**：输出的剧本可直接阅读和修改

### 5.2 Schema定义

```yaml
# ============================================================
# 剧本YAML Schema v1.0
# 用于AI小说转剧本工具的输出格式
# 遵循中国影视剧本标准格式
# ============================================================

script:
  # ---- 元数据 ----
  metadata:
    title: string              # 剧本标题
    original_author: string    # 原作者
    adapter: string            # 改编者（AI/人工）
    genre: string              # 题材类型（言情/悬疑/科幻/历史/都市/古装等）
    total_episodes: int        # 总幕数
    total_scenes: int          # 总场景数
    created_at: datetime       # 创建时间
    version: string            # Schema版本号
    synopsis: string           # 剧本简介（可选）

  # ---- 角色表 ----
  characters:
    - name: string             # 角色名称
      role_type: string        # 角色类型（见下方枚举）
      description: string      # 角色描述
      gender: string           # 性别（可选）
      age: string              # 年龄段（可选）
      appearance: string       # 外貌特征（可选）
      personality: string      # 性格特点（可选）
      relationship: string     # 与其他角色关系（可选）

  # ---- 剧本内容 ----
  episodes:
    - episode_number: int      # 幕序号
      title: string            # 幕标题
      summary: string          # 幕概要（可选）

      scenes:
        - scene_number: int    # 场景序号
          scene_header: string # 场景标题行（格式：地点 时间 内外景）
          content: string      # 场景内容（纯文本，包含描写和对话）
```

### 5.3 角色类型枚举

```yaml
role_type枚举值：
  主要角色：
    - 男主          # 男性主角
    - 女主          # 女性主角
  
  重要角色：
    - 男二          # 男性二号角色
    - 女二          # 女性二号角色
    - 重要配角      # 戏份较多的配角
  
  次要角色：
    - 次要配角      # 戏份较少的配角
    - 龙套          # 只有几句台词或少量戏份
    - 群众          # 无台词的背景人物
  
  特殊角色：
    - 画外音        # 旁白或内心独白
    - 旁白          # 叙述者
```

### 5.4 scene_header 格式规范

```
格式：「地点 时间 内外景」

示例：
  - 出租屋 夜 内
  - 医院走廊 日 内
  - 公园湖边 黄昏 外
  - 办公室 日 内
  - 山顶 清晨 外
  - 火车站台 雨夜 外

说明：
  - 地点：具体场景位置
  - 时间：日/夜/清晨/黄昏/傍晚/深夜/凌晨等
  - 内外景：内/外/内外（表示室内/室外/室内外）
```

### 5.6 格式说明

| 要素 | 格式要求 | 示例 |
|------|----------|------|
| 场景标题 | 独占一行，无缩进 | `出租屋 夜 内` |
| 场景描写 | 连贯的叙述性文字 | `桌上饭菜热气腾腾，李国才在客厅摆放碗筷。` |
| 角色对话 | 角色名 + 冒号 + 台词 | `小婉：国才，袄子全干了么？` |
| 带动作的对话 | 角色名（动作）+ 冒号 + 台词 | `易国才（盛着汤）：干了吧。` |
| 角色动作 | 连贯的叙述性文字 | `易国才盛好两碗汤放在桌上。` |
| 内心活动 | 通过描写自然表现 | `小婉愣了一下，看着手中的红棉袄。` |

### 5.7 设计说明

| 设计决策 | 原因 |
|---------|------|
| content使用纯文本 | 保持剧本的连贯性和可读性，符合行业标准 |
| 不拆分对话/动作/旁白 | 避免碎片化，让剧本更自然流畅 |
| 不使用镜头指示 | 通过行文自然表现调度，留给导演和摄影发挥空间 |
| scene_header标准化 | 遵循影视剧本场景标题规范 |
| 角色类型细化 | 便于角色管理和统计 |
| 保留YAML结构 | 便于程序解析和存储 |

## 十、风险评估与应对

| 风险项 | 风险等级 | 影响 | 应对措施 |
|--------|----------|------|----------|
| 百炼API调用失败 | 高 | 无法完成转换 | 1. 实现重试机制（最多3次）<br>2. 设置合理超时时间<br>3. 提供友好错误提示 |
| 长文本处理超时 | 中 | 大文件转换失败 | 1. 分章节调用API<br>2. 使用流式输出<br>3. 异步处理+进度反馈 |
| 章节识别不准确 | 中 | 转换结果不理想 | 1. 支持多种章节格式<br>2. 提供手动调整功能<br>3. 持续优化匹配规则 |
| YAML格式错误 | 低 | 剧本无法使用 | 1. 严格Schema验证<br>2. 生成后自动校验<br>3. 提供修复建议 |
| 并发性能问题 | 低 | 响应缓慢 | 1. 异步处理<br>2. 队列管理<br>3. 资源池优化 |
