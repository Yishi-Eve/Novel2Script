# AI小说转剧本工具 - 项目计划书

## 一、项目概述

### 1.1 项目背景

很多小说作者希望将自己的作品改编成剧本，但剧本创作门槛较高，需要掌握专业的格式和技巧。本项目旨在开发一款AI辅助剧本创作工具，通过大模型自动将小说文本转换为结构化剧本，降低改编门槛，提升创作效率。

### 1.2 项目目标

开发一款Web应用，能够：
- 接收3个章节以上的小说文本（支持txt、md、docx格式）
- 自动识别章节结构
- 调用AI大模型将小说转换为结构化剧本
- 输出符合规范的YAML格式剧本
- 支持在线预览和下载

### 1.3 项目信息

| 项目名称 | AI小说转剧本工具 |
|---------|----------------|
| 项目代号 | Novel2Script |
| 版本号 | v1.0.0 |
| 开发周期 | 3天 |
| 目标用户 | 小说作者、编剧、内容创作者 |

## 五、YAML Schema 设计

### 5.1 设计原则

1. **结构清晰**：层次分明，便于阅读和编辑
2. **信息完整**：包含剧本所需的所有元素
3. **易于扩展**：支持后续功能扩展
4. **标准兼容**：参考专业剧本格式规范

### 5.2 Schema定义

```yaml
# ============================================================
# 剧本YAML Schema v1.0
# 用于AI小说转剧本工具的输出格式
# ============================================================

script:
  # ---- 元数据 ----
  metadata:
    title: string          # 剧本标题
    original_author: string # 原作者
    adapter: string        # 改编者（AI/人工）
    genre: string          # 题材类型（言情/悬疑/科幻/历史等）
    total_episodes: int    # 总幕数
    total_scenes: int      # 总场景数
    created_at: datetime   # 创建时间
    version: string        # Schema版本号
    synopsis: string       # 剧本简介（可选）

  # ---- 角色表 ----
  characters:
    - name: string           # 角色名称
      description: string    # 角色描述
      role_type: string      # 角色类型：MAIN/SUPPORTING/MINOR/EXTRA
      gender: string         # 性别（可选）
      age: string            # 年龄段（可选）
      appearance: string     # 外貌描述（可选）
      personality: string    # 性格特点（可选）

  # ---- 剧本内容 ----
  episodes:
    - episode_number: int    # 幕序号
      title: string          # 幕标题
      summary: string        # 幕概要

      scenes:
        - scene_number: int  # 场景序号
          location: string   # 场景地点
          time: string       # 时间（白天/夜晚/清晨/黄昏等）
          weather: string    # 天气（可选）
          season: string     # 季节（可选）
          description: string # 场景描述

          # 出场角色
          characters_present:
            - string         # 角色名称列表

          # 内容序列
          content:
            # 旁白/叙述
            - type: narration
              text: string

            # 对话
            - type: dialogue
              speaker: string    # 说话者
              listener: string   # 倾听者（可选）
              line: string       # 台词
              action: string     # 动作描述（可选）
              emotion: string    # 情感状态（可选）
              tone: string       # 语气（可选）

            # 动作/舞台指示
            - type: action
              character: string  # 执行角色
              description: string # 动作描述

            # 画外音
            - type: voiceover
              character: string  # 角色
              text: string       # 画外音内容

            # 旁白字幕
            - type: subtitle
              text: string       # 字幕内容

            # 转场
            - type: transition
              description: string # 转场说明

            # 音效提示
            - type: sound
              description: string # 音效描述

            # 镜头指示
            - type: camera
              description: string # 镜头描述
```

### 5.4 设计说明

| 设计决策 | 原因 |
|---------|------|
| 采用层次结构 | 便于理解和编辑，符合YAML最佳实践 |
| 分离元数据和内容 | 元数据便于检索，内容便于阅读 |
| 支持多种内容类型 | 涵盖剧本所有常见元素 |
| 角色信息独立管理 | 便于角色查询和一致性检查 |
| 保留可选字段 | 兼顾信息完整性和灵活性 |
| 使用枚举类型 | 便于数据统计和筛选 |

## 十、风险评估与应对

| 风险项 | 风险等级 | 影响 | 应对措施 |
|--------|----------|------|----------|
| 百炼API调用失败 | 高 | 无法完成转换 | 1. 实现重试机制（最多3次）<br>2. 设置合理超时时间<br>3. 提供友好错误提示 |
| 长文本处理超时 | 中 | 大文件转换失败 | 1. 分章节调用API<br>2. 使用流式输出<br>3. 异步处理+进度反馈 |
| 章节识别不准确 | 中 | 转换结果不理想 | 1. 支持多种章节格式<br>2. 提供手动调整功能<br>3. 持续优化匹配规则 |
| YAML格式错误 | 低 | 剧本无法使用 | 1. 严格Schema验证<br>2. 生成后自动校验<br>3. 提供修复建议 |
| 并发性能问题 | 低 | 响应缓慢 | 1. 异步处理<br>2. 队列管理<br>3. 资源池优化 |
