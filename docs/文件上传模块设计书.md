# 文件上传模块设计书

## 一、模块概述

### 1.1 模块定位

文件上传模块（FileStorageService）是Novel2Script系统的入口模块，负责接收用户上传的小说文件，进行格式验证和安全检查，将文件存储到服务器，并记录文件元数据到数据库，为后续的文本解析和转换提供基础数据。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 格式兼容 | 支持txt、md、docx三种文档格式上传 |
| 安全可靠 | 文件类型验证、大小限制、防恶意上传 |
| 存储稳定 | UUID重命名、目录结构清晰、路径可配置 |
| 元数据完整 | 记录文件名、大小、类型、上传时间等信息 |
| 易于扩展 | 支持后续扩展更多文件格式 |

## 二、功能需求

### 2.1 功能列表

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-001 | 文件上传 | P0 | 接收multipart/form-data文件上传 |
| F-002 | 格式验证 | P0 | 验证文件扩展名和MIME类型 |
| F-003 | 大小限制 | P0 | 限制文件大小不超过10MB |
| F-004 | 文件存储 | P0 | UUID重命名存储到本地磁盘 |
| F-005 | 元数据保存 | P0 | 保存文件信息到数据库 |
| F-006 | 文件删除 | P1 | 支持删除已上传的文件 |
| F-007 | 文件查询 | P1 | 根据ID查询文件信息 |

### 2.2 输入输出

**输入：**
- MultipartFile：上传的文件对象

**输出：**
- NovelUploadVO对象，包含：
  - id：文件ID
  - originalFilename：原始文件名
  - storedFilename：存储文件名
  - fileType：文件类型
  - fileSize：文件大小
  - status：状态
  - uploadTime：上传时间

### 2.3 业务规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-001 | 文件大小不得超过10MB |
| BR-002 | 仅支持txt、md、docx三种格式 |
| BR-003 | 文件名不能为空 |
| BR-004 | 文件内容不能为空 |
| BR-005 | 使用UUID重命名防止文件名冲突 |
| BR-006 | 按日期分目录存储便于管理 |
| BR-007 | 上传成功后状态为UPLOADED |

## 三、接口设计

### 3.1 RESTful API

| 方法 | 路径 | 说明 | 请求参数 | 响应 |
|------|------|------|----------|------|
| POST | /api/novel/upload | 上传小说文件 | multipart/form-data | NovelUploadVO |
| GET | /api/novel/{id} | 获取小说信息 | - | NovelUploadVO |
| GET | /api/novels | 获取小说列表 | page, size | PageResult |
| DELETE | /api/novel/{id} | 删除小说 | - | Result |

### 3.2 服务接口

FileStorageService 提供五个核心方法：

- **store(file)**：存储文件
  - 验证文件有效性
  - 生成存储路径
  - 保存文件到磁盘
  - 保存元数据到数据库
  - 返回 NovelUpload 实体

- **delete(fileId)**：删除文件
  - 查询文件信息
  - 删除物理文件
  - 删除数据库记录

- **getFile(fileId)**：获取文件信息
  - 根据ID查询数据库
  - 返回 NovelUpload 实体

- **listFiles(pageable)**：获取文件列表
  - 使用MyBatis Plus分页查询
  - 按上传时间倒序排列

- **getFilePath(fileId)**：获取文件路径
  - 查询文件信息
  - 拼接绝对路径返回

### 3.3 数据传输对象

#### NovelUploadVO（响应对象）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 文件ID |
| originalFilename | String | 原始文件名 |
| storedFilename | String | 存储文件名 |
| fileType | String | 文件类型 |
| fileSize | Long | 文件大小（字节） |
| fileSizeFormatted | String | 文件大小（可读格式） |
| status | String | 状态 |
| uploadTime | LocalDateTime | 上传时间 |

#### Result（通用响应）

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码 |
| message | String | 消息 |
| data | T | 数据 |

提供两个静态工厂方法：
- success(data)：成功响应，code=200
- error(code, message)：错误响应

#### PageResult（分页响应）

| 字段 | 类型 | 说明 |
|------|------|------|
| content | List<T> | 数据列表 |
| totalElements | long | 总记录数 |
| totalPages | int | 总页数 |
| pageNumber | int | 当前页码 |
| pageSize | int | 每页大小 |

## 四、数据库设计

### 4.1 设计原则

1. **只存储文件路径**：不存储文件内容，需要时读取文件路径再获取内容
2. **减少数据库压力**：避免大文本字段影响查询性能
3. **文件系统更适合**：大文件存储在文件系统中，数据库只存元数据

### 4.2 实体类

NovelUpload 实体字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Long | 主键，自增 |
| originalFilename | String | 原始文件名 |
| storedFilename | String | 存储文件名（UUID） |
| filePath | String | 文件存储路径 |
| fileSize | Long | 文件大小（字节） |
| fileType | String | 文件类型 |
| chapterCount | Integer | 识别到的章节数 |
| status | NovelStatus | 状态 |
| uploadTime | LocalDateTime | 上传时间 |
| updateTime | LocalDateTime | 更新时间 |

### 4.3 枚举定义

NovelStatus 枚举定义四种状态：

| 枚举值 | 描述 |
|--------|------|
| UPLOADED | 已上传 |
| PARSING | 解析中 |
| PARSED | 解析完成 |
| ERROR | 解析失败 |

### 4.4 Mapper接口

NovelUploadMapper 继承 BaseMapper，提供两个自定义查询：

- **selectByStatus(status)**：根据状态查询
- **selectByFileType(fileType)**：根据文件类型查询

### 4.5 表结构

novel_upload 表结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| original_filename | VARCHAR(255) | 原始文件名 |
| stored_filename | VARCHAR(255) | 存储文件名 |
| file_path | VARCHAR(500) | 文件存储路径 |
| file_size | BIGINT | 文件大小 |
| file_type | VARCHAR(20) | 文件类型 |
| chapter_count | INT | 章节数 |
| status | VARCHAR(20) | 状态 |
| upload_time | DATETIME | 上传时间 |
| update_time | DATETIME | 更新时间 |

索引：
- idx_status：状态索引
- idx_file_type：文件类型索引

### 5.2 核心类调用关系

#### NovelController

依赖 FileStorageService，处理HTTP请求。

**uploadNovel 方法调用流程：**
1. 接收 MultipartFile
2. 调用 fileStorageService.store 存储文件
3. 转换为 NovelUploadVO
4. 返回 Result.success

**getNovel 方法调用流程：**
1. 接收文件ID
2. 调用 fileStorageService.getFile 获取文件信息
3. 转换为 NovelUploadVO
4. 返回 Result.success

**listNovels 方法调用流程：**
1. 接收分页参数
2. 调用 fileStorageService.listFiles 获取分页数据
3. 转换为 NovelUploadVO 列表
4. 构建 PageResult
5. 返回 Result.success

**deleteNovel 方法调用流程：**
1. 接收文件ID
2. 调用 fileStorageService.delete 删除文件
3. 返回 Result.success

#### FileStorageServiceImpl

依赖 NovelUploadMapper 和 StorageProperties。

**store 方法调用流程：**
1. 调用 validateFile 验证文件
2. 提取文件信息（名称、扩展名、大小）
3. 调用 generateStoredFilename 生成UUID文件名
4. 调用 generateRelativePath 生成日期目录路径
5. 创建目录
6. 保存文件到磁盘
7. 构建 NovelUpload 实体
8. 调用 novelUploadMapper.insert 保存元数据
9. 返回 NovelUpload

**delete 方法调用流程：**
1. 调用 novelUploadMapper.selectById 查询文件信息
2. 拼接文件绝对路径
3. 删除物理文件
4. 调用 novelUploadMapper.deleteById 删除数据库记录

**validateFile 方法调用流程：**
1. 检查文件是否为空
2. 检查文件名是否为空
3. 调用 getFileExtension 提取扩展名
4. 检查扩展名是否在支持列表中
5. 检查文件大小是否超限

**generateStoredFilename 算法：**
- storedFilename = UUID.randomUUID() + "." + extension

**generateRelativePath 算法：**
- datePath = 当前日期格式化为 "yyyy/MM/dd"
- relativePath = datePath + "/" + storedFilename

#### StorageProperties

配置属性类，包含：
- basePath：基础存储路径（默认 ./uploads）
- novelPath：小说文件存储路径
- scriptPath：剧本文件存储路径

通过 @PostConstruct 初始化默认路径。

## 六、算法设计

### 6.1 文件存储路径算法

```
输入：原始文件名 originalFilename
输出：相对存储路径 relativePath

1. 提取文件扩展名 extension
   - 从文件名中获取最后一个"."后的内容
   - 转换为小写

2. 生成UUID文件名 storedFilename
   - storedFilename = UUID.randomUUID() + "." + extension

3. 生成日期目录 datePath
   - 获取当前日期
   - 格式化为 "yyyy/MM/dd"

4. 拼接相对路径
   - relativePath = datePath + "/" + storedFilename

返回 relativePath
```

### 6.2 文件验证算法

```
输入：MultipartFile file
输出：验证结果（通过/抛出异常）

1. 检查文件是否为空
   - 如果 file.isEmpty() 为 true，抛出异常

2. 检查文件名
   - 如果 originalFilename 为空或空白，抛出异常

3. 检查文件类型
   - 提取扩展名
   - 如果不在支持列表中，抛出异常

4. 检查文件大小
   - 如果 file.getSize() > 10MB，抛出异常

返回 通过
```

### 6.3 文件大小格式化算法

```
输入：文件大小 size（字节）
输出：可读格式 formattedSize

1. 如果 size < 1024
   - 返回 size + " B"

2. 如果 size < 1024 * 1024
   - 返回 size / 1024.0 + " KB"（保留2位小数）

3. 否则
   - 返回 size / (1024.0 * 1024) + " MB"（保留2位小数）

返回 formattedSize
```
