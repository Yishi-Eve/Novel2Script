# 章节分割模块设计书

## 一、模块概述

### 1.1 模块定位

章节分割模块（ChapterSplitterService）是Novel2Script系统的核心处理模块，负责将文本解析模块输出的纯文本内容按照章节结构进行智能识别和分割，为后续的AI转换提供结构化的章节数据。该模块是连接文本解析与AI转换的桥梁，直接影响最终剧本的质量。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 格式兼容 | 支持多种常见章节标记格式（第X章、Chapter X、卷X篇X等） |
| 识别准确 | 基于正则表达式和启发式规则，准确识别章节边界 |
| 结果持久化 | 将分割结果保存为JSON文件，便于后续查询和调试 |
| 章节验证 | 确保识别到的章节数不少于3个（项目要求） |
| 性能高效 | 大文件处理流畅，内存占用合理 |

### 1.3 依赖关系

```
┌─────────────────────┐
│    文本解析模块      │
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│    章节分割模块      │◄──── 本模块
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
```

## 二、处理流程

### 2.1 整体流程

```
文本解析模块输出 cleanText（已完成清洗）
           │
           ▼
┌─────────────────────────────────────┐
│  章节分割模块（ChapterSplitterService）│
│  ① 正则匹配章节标题                   │
│  ② 过滤误匹配（目录、注释等）         │
│  ③ 分割章节内容                       │
│  ④ 验证章节数量（≥3）                 │
│  ⑤ 生成章节元数据                     │
│  ⑥ 保存结果到JSON文件                 │
└─────────────────────────────────────┘
           │
           │ 传递：章节列表 + 文件路径
           ▼
┌─────────────────────────────────────┐
│  AI转换模块                          │
│  - 逐章读取内容                       │
│  - 调用百炼API转换                    │
└─────────────────────────────────────┘
```

### 2.2 分割流程详解

**步骤1：正则匹配章节标题**
- 输入：cleanText（文本解析模块输出，已完成清洗）
- 逻辑：使用预定义的正则表达式模式匹配章节标题
- 输出：候选章节标题列表（包含位置信息）

**步骤2：过滤误匹配**
- 输入：候选章节标题列表
- 逻辑：过滤目录、注释、引文中的误匹配
- 输出：有效章节标题列表

**步骤3：分割章节内容**
- 输入：有效章节标题列表 + 原始文本
- 逻辑：根据标题位置分割文本
- 输出：章节内容列表

**步骤4：验证章节数量**
- 输入：章节内容列表
- 逻辑：检查章节数是否≥3
- 输出：验证结果（不满足则抛出异常）

**步骤5：生成章节元数据**
- 输入：章节内容列表
- 逻辑：计算每章的字符数、行数等信息
- 输出：完整的章节列表

**步骤6：保存结果到JSON文件**
- 输入：章节列表
- 逻辑：序列化为JSON并保存到文件系统
- 输出：JSON文件路径

## 三、功能需求

### 3.1 功能列表

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-001 | 章节标题识别 | P0 | 基于正则表达式识别常见章节格式 |
| F-002 | 章节内容分割 | P0 | 根据标题位置分割章节内容 |
| F-003 | 章节数量验证 | P0 | 确保章节数不少于3个 |
| F-004 | 结果持久化 | P0 | 将分割结果保存为JSON文件 |
| F-005 | 误匹配过滤 | P1 | 过滤目录、注释中的误匹配 |
| F-006 | 自定义正则 | P1 | 支持用户自定义章节匹配规则 |
| F-007 | 章节预览 | P2 | 提供章节分割结果预览 |

### 3.2 输入输出

**输入：**
- novelId：小说ID（Long）
- cleanText：清洗后的文本内容（String，来自文本解析模块）

**输出：**
- ChapterSplitResult对象，包含：
  - novelId：小说ID
  - chapterCount：章节数量
  - chapters：章节列表
  - chapterFilePath：JSON文件路径
  - splitTime：分割耗时（毫秒）

### 3.3 支持的章节格式

| 格式类型 | 匹配模式 | 示例 |
|----------|----------|------|
| 中文章节 | `第[零一二三四五六七八九十百千万\d]+[章回节卷集部篇]` | 第一章、第1章、第十二回、第一卷、第一篇 |
| 英文章节 | `Chapter\s+\d+` | Chapter 1、Chapter One |

**说明：**
- 移除了数字开头格式（如 `1 开篇`），因为容易与日期、数量等普通文本混淆，误匹配率高
- 移除了卷篇格式（如 `卷一`、`篇二`），因为与中文章节格式重复（`第一卷`、`第一篇`已被覆盖）
- 移除了罗马数字格式（如 `Ⅰ.`、`Ⅱ`），因为使用场景较少且目录检测算法不支持
- 移除了分隔符格式（如 `===`、`---`），因为语义不明确，可能是章节分隔也可能是场景切换

**注意事项：** 前端页面需要展示支持的章节格式示例，让用户明确知道什么样的格式能够被系统识别，避免因格式不规范导致章节识别失败。

### 3.4 业务规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-001 | 章节数量不得少于3个 |
| BR-002 | 章节标题不能为空 |
| BR-003 | 章节内容不能为空 |
| BR-004 | 章节顺序必须与原文一致 |
| BR-005 | 目录区域的章节标题应被过滤 |
| BR-006 | 章节分割结果必须保存到文件 |

## 四、接口设计

### 4.1 服务接口

ChapterSplitterService 提供三个核心方法：

- **splitChapters(novelId, cleanText)**：执行章节分割
  - 调用章节标题识别
  - 调用内容分割
  - 验证章节数量
  - 保存结果到文件
  - 返回 ChapterSplitResult

- **detectChapterTitles(text)**：识别章节标题
  - 使用正则表达式匹配
  - 过滤误匹配
  - 返回标题列表（包含位置信息）

- **loadChapters(filePath)**：从JSON文件加载章节
  - 读取JSON文件
  - 反序列化为章节列表
  - 返回 List<Chapter>

负责使用正则表达式识别章节标题。

- customPatterns：用户自定义的正则表达式

**核心方法：**

  - 遍历所有模式进行匹配
  - 收集匹配结果（标题、位置、模式）
  - 按位置排序返回

#### ChapterPattern（章节模式）

定义章节匹配的正则表达式模式。

**预定义模式：**
- CHINESE_CHAPTER：`第[零一二三四五六七八九十百千万\d]+[章回节卷集部篇]`
- ENGLISH_CHAPTER：`Chapter\s+\d+`

**说明：**
- 不包含数字开头格式，因为容易与日期、数量等普通文本混淆
- 不包含卷篇格式，因为与中文章节格式重复（`第一卷`、`第一篇`已被 `CHINESE_CHAPTER` 覆盖）
- 不包含罗马数字格式，因为使用场景较少且目录检测算法不支持
- 不包含分隔符格式，因为语义不明确，可能是章节分隔也可能是场景切换

#### ChapterFilter（过滤器）

负责过滤误匹配的章节标题。

**过滤规则：**
- 过滤目录区域的标题（通常在文本开头，连续出现多个标题）
- 过滤引文、注释中的标题
- 过滤过短的标题（少于2个字符）
- 过滤过长的标题（超过50个字符）

#### ChapterSplitException（异常类）

继承 RuntimeException，提供两个构造方法：
- message：异常消息
- message + cause：异常消息和原因链

## 七、算法设计

### 7.1 章节标题检测算法

```
输入：文本内容 text
输出：章节标题列表 titles

1. 初始化结果列表 titles = []

2. 遍历预定义的正则表达式模式 patterns
   a. 使用模式 pattern 编译正则表达式 regex
   b. 创建 Matcher 对 matcher = regex.matcher(text)
   c. 循环查找匹配：
      while (matcher.find()) {
          title = matcher.group()      // 匹配的标题文本
          position = matcher.start()   // 起始位置
          titles.add(new ChapterTitle(title, position, pattern.name()))
      }

3. 按 position 排序 titles

4. 去重：如果多个模式匹配到同一位置，保留第一个

返回 titles
```

### 7.2 误匹配过滤算法

```
输入：章节标题列表 titles，原始文本 text
输出：过滤后的标题列表 filteredTitles

1. 检测目录区域（重复标题检测）：
   for i = 0 to titles.size - 1:
       currentTitle = titles[i].title
       // 检查标题是否包含第一章的关键词（"一"、"1"、"Chapter 1"等）
       if isFirstChapterTitle(currentTitle):
           // 查找后面是否有相同的标题
           for j = i + 1 to titles.size - 1:
               if titles[j].title.equals(currentTitle):
                   // 找到重复标题，从j位置开始返回（跳过目录）
                   titles = titles.subList(j, titles.size)
                   break

2. 过滤无效标题：
   for each title in titles:
       if title.length < 2:  // 过短
           skip
       if title.length > 50:  // 过长
           skip
       filteredTitles.add(title)

3. 返回 filteredTitles

说明：目录区域的特征是会重复列出所有章节标题，正文开始时会再次出现第一个章节标题。
通过检测重复出现的第一个章节标题，可以准确识别目录区域的结束位置。
```

### 7.3 章节分割算法

```
输入：过滤后的标题列表 titles，原始文本 text
输出：章节列表 chapters

1. 初始化章节列表 chapters = []

2. 如果 titles 为空：
   - 将整个文本作为一个章节返回

3. 处理第一个章节（标题前的内容）：
   - 如果第一个标题位置 > 0：
     - 将标题前的内容作为"序章"或"前言"
     - 或者忽略（根据配置）

4. 分割章节：
   for i = 0 to titles.length - 1:
       start = titles[i].position
       end = (i < titles.length - 1) ? titles[i+1].position : text.length
       
       title = titles[i].title
       content = text.substring(start + title.length, end).trim()
       
       chapters.add(new Chapter(i+1, title, content))

5. 返回 chapters
```

### 7.4 目录检测算法

```
输入：标题列表 titles
输出：跳过目录后的标题列表

1. 如果 titles.size < 3:
   return titles

2. 遍历标题列表：
   for i = 0 to titles.size - 1:
       currentTitle = titles[i].title
       
       // 检查是否是第一章的标题
       if isFirstChapterTitle(currentTitle):
           // 查找后面是否有相同的标题
           for j = i + 1 to titles.size - 1:
               if titles[j].title.equals(currentTitle):
                   // 找到重复标题，返回从j位置开始的列表
                   return titles.subList(j, titles.size)

3. 没有找到重复标题，返回原列表

isFirstChapterTitle(title) 判断逻辑（精确匹配，避免误判）：
   - 中文：使用正则 `^第[一1][章回节卷集部篇]` 精确匹配"第一章"或"第1章"
     - ✅ 匹配：第一章、第1章
     - ❌ 不匹配：第十一章、第二十一章、第一百章
   - 英文：使用正则 `^Chapter\s+(1|One)` 精确匹配"Chapter 1"或"Chapter One"
     - ✅ 匹配：Chapter 1、Chapter One
     - ❌ 不匹配：Chapter 11、Chapter Twenty

示例：
   标题列表：
   [0] "第一章 初入江湖 .................. 1"  ← 目录
   [1] "第二章 奇遇 .................... 15"  ← 目录
   [2] "第三章 危机 .................... 28"  ← 目录
   [3] "第一章 初入江湖"                      ← 正文开始
   
   检测过程：
   - i=0: currentTitle="第一章 初入江湖 .................. 1"
   - isFirstChapterTitle? → true（正则匹配"第一章"）
   - 提取核心标题：extractCoreTitle("第一章 初入江湖 .................. 1") → "第一章初入江湖"
   - j=3: extractCoreTitle("第一章 初入江湖") → "第一章初入江湖" == 核心标题
   - 找到重复标题，返回从j位置开始的列表
   
边界情况：
   - "第十一章"不会被误判为"第一章"（正则不匹配）
   - "第1章"会被正确识别为第一章（正则匹配）
   - "Chapter 11"不会被误判为"Chapter 1"（正则不匹配）
```

### 7.5 文件保存算法

```
输入：ChapterSplitResult result，存储路径 basePath
输出：文件路径 filePath

1. 生成文件名：
   fileName = "novel_" + result.novelId + "_chapters.json"

2. 拼接完整路径：
   filePath = basePath + "/chapters/" + fileName

3. 创建目录：
   Files.createDirectories(parentPath)

4. 序列化为JSON：
   json = objectMapper.writeValueAsString(result)

5. 写入文件：
   Files.writeString(filePath, json, StandardCharsets.UTF_8)

6. 返回 filePath
```

## 八、异常处理

### 8.1 异常类定义

ChapterSplitException 继承 RuntimeException，提供两个构造方法：
- message：异常消息
- message + cause：异常消息和原因链

### 8.2 异常场景

| 异常场景 | 异常类型 | 处理方式 |
|----------|----------|----------|
| 文本为空 | ChapterSplitException | 抛出异常，提示文本为空 |
| 章节数少于3个 | ChapterSplitException | 抛出异常，提示章节数不足 |
| 章节标题为空 | ChapterSplitException | 抛出异常，提示标题为空 |
| 章节内容为空 | ChapterSplitException | 抛出异常，提示内容为空 |
| JSON文件写入失败 | IOException | 捕获并转换为ChapterSplitException |
| 数据库更新失败 | DataAccessException | 捕获并转换为ChapterSplitException |

### 8.3 全局异常处理

GlobalExceptionHandler 新增处理：
- ChapterSplitException -> 返回 400 状态码

### 9.1 chapter-splitter 配置

| 配置项 | 默认值 | 说明 |

```yaml
  custom-patterns: []

storage:
```
