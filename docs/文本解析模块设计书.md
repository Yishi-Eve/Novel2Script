# 文本解析模块设计书

## 一、模块概述

### 1.1 模块定位

文本解析模块（TextParserService）是Novel2Script系统的核心基础模块，负责将用户上传的不同格式的小说文件解析为统一的纯文本格式，为后续的章节分割和AI转换提供标准化的输入数据。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 格式兼容 | 支持txt、md、docx三种主流文档格式 |
| 内容准确 | 完整提取文本内容，保留原始结构 |
| 编码兼容 | 支持UTF-8、GBK等常见中文编码 |
| 错误容错 | 优雅处理格式错误和异常情况 |
| 性能高效 | 大文件处理流畅，内存占用合理 |

### 1.3 依赖关系

```

│    文件上传模块      │

           │
           ▼
┌─────────────────────┐

└──────────┬──────────┘
           │
           ▼
```

## 二、处理流程

### 2.1 整体流程

```
用户上传文件
    │
    ▼
┌─────────────────────────────────────┐
│  文件上传模块（FileStorageService）   │
│  - 验证文件格式和大小                │
│  - 识别文件类型（txt/md/docx）       │
│  - 存储文件到磁盘                    │
│  - 保存元数据到数据库                │
└─────────────────────────────────────┘
    │
    │ 传递：文件路径 + 文件类型
    ▼
┌─────────────────────────────────────┐
│  文本解析模块（TextParserService）    │
│  ① 根据文件类型选择解析器            │
│  ② 解析器提取文本内容                │
│  ③ 清洗文本（统一格式、去除空白）    │
│  ④ 返回标准化的纯文本                │
└─────────────────────────────────────┘
    │
    │ 传递：cleanText（清洗后的纯文本）
    ▼
┌─────────────────────────────────────┐
│  章节分割模块                        │
│  - 识别章节标题                      │
│  - 分割章节内容                      │
└─────────────────────────────────────┘
```

### 2.2 解析流程详解

文本解析的核心流程分为三步：

**步骤1：选择解析器**
- 输入：文件类型（FileType枚举）
- 逻辑：根据FileType从解析器映射表中获取对应的FileParser实现
- 输出：对应的解析器实例（TxtFileParser/MdFileParser/DocxFileParser）

**步骤2：解析文件提取文本**
- 输入：文件路径
- 逻辑：
  - TXT：检测编码 → 读取文件内容 → 得到rawText
  - MD：读取Markdown源码 → 转换为纯文本 → 得到rawText
  - DOCX：打开文档 → 提取段落和表格文本 → 得到rawText
- 输出：原始文本内容（rawText）

**步骤3：清洗文本**
- 输入：原始文本（rawText）
- 逻辑：统一换行符 → 去除多余空行 → 去除行首尾空白
- 输出：清洗后的文本（cleanText）

### 2.3 与文件上传模块的衔接

文件上传模块已完成以下工作，文本解析模块无需重复：
- 文件格式验证（扩展名检查）
- 文件大小验证（10MB限制）
- 文件类型识别（已确定FileType）
- 文件存储（已保存到磁盘）

文本解析模块接收的输入：
- 文件路径：由文件上传模块返回的存储路径
- 文件类型：由文件上传模块识别的FileType枚举

## 三、功能需求

### 3.1 功能列表

| 编号 | 功能 | 优先级 | 说明 |
|------|------|--------|------|
| F-001 | TXT文件解析 | P0 | 纯文本文件解析，支持多种编码 |
| F-002 | MD文件解析 | P0 | Markdown文件解析，提取纯文本 |
| F-003 | DOCX文件解析 | P0 | Word文档解析，提取文本内容 |
| F-004 | 编码自动检测 | P1 | 自动识别文件编码格式 |
| F-005 | 文本清洗 | P1 | 去除多余空白、特殊字符 |
| F-006 | 格式验证 | P0 | 验证文件格式和内容有效性 |

### 3.2 输入输出

**输入：**
- 文件路径：String
- 文件类型：FileType枚举（TXT/MD/DOCX）

**输出：**
- ParseResult对象，包含：
  - rawText：原始文本内容
  - cleanText：清洗后的文本
  - fileType：文件类型
  - fileSize：文件大小
  - encoding：检测到的编码（txt文件）
  - charCount：字符数
  - lineCount：行数

### 3.3 业务规则

| 规则编号 | 规则描述 |
|----------|----------|
| BR-001 | 文件大小不得超过10MB |
| BR-002 | 文件内容不能为空 |
| BR-003 | TXT文件必须为文本文件，不能是二进制文件 |
| BR-004 | MD文件必须包含有效的Markdown内容 |
| BR-005 | DOCX文件必须为有效的Office Open XML格式 |

## 四、接口设计

### 4.1 服务接口

TextParserService 提供两个核心方法：

- **parse(filePath, fileType)**：解析文件并返回ParseResult对象
  - 根据fileType获取对应的解析器
  - 验证文件有效性
  - 执行解析并记录耗时
  - 返回解析结果

- **canParse(filePath, fileType)**：验证文件是否可解析
  - 检查解析器是否存在
  - 调用解析器验证文件

### 4.2 数据传输对象

ParseResult 包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| rawText | String | 原始文本内容 |
| cleanText | String | 清洗后的文本 |
| fileType | FileType | 文件类型 |
| fileSize | Long | 文件大小（字节） |
| encoding | String | 文件编码（仅TXT） |
| charCount | Integer | 字符数 |
| lineCount | Integer | 行数 |
| parseTime | Long | 解析耗时（毫秒） |

### 4.3 枚举定义

FileType 枚举定义三种文件类型：

| 枚举值 | 扩展名 | 描述 |
|--------|--------|------|
| TXT | txt | 纯文本文件 |
| MD | md | Markdown文件 |
| DOCX | docx | Word文档 |

提供 fromExtension 方法，根据扩展名获取对应的FileType。

```
└── FileType                       # 文件类型枚举

└── FileParseException             # 解析异常
```

### 5.2 解析器接口

FileParser 接口定义三个方法：

- **getSupportedType()**：返回支持的FileType
- **parse(filePath)**：解析文件并返回ParseResult
- **isValid(filePath)**：验证文件是否有效

### 5.3 核心类调用关系

#### TextParserServiceImpl

采用**策略模式**，通过Spring自动注入所有FileParser实现，构建 FileType -> FileParser 的映射表。

**parse 方法调用流程：**
1. 从映射表获取对应解析器
2. 调用解析器的 isValid 验证文件
3. 调用解析器的 parse 执行解析
4. 记录解析耗时
5. 返回 ParseResult

#### TxtFileParser

依赖 EncodingDetector 进行编码检测。

**parse 方法调用流程：**
1. 调用 EncodingDetector.detect 检测编码
2. 使用检测到的编码读取文件
3. 调用 cleanText 清洗文本
4. 构建 ParseResult 返回

**isValid 方法调用流程：**
1. 检查文件是否存在
2. 检查文件大小是否超限
3. 调用 isTextFile 判断是否为文本文件

#### MdFileParser

使用 CommonMark 库解析 Markdown。

**parse 方法调用流程：**
1. 读取 Markdown 内容
2. 使用 Parser 解析为 AST
3. 使用 TextContentRenderer 渲染为纯文本
4. 调用 cleanText 清洗文本
5. 构建 ParseResult 返回

**isValid 方法调用流程：**
1. 检查文件是否存在
2. 检查文件大小是否超限
3. 检查文件扩展名是否为 .md 或 .markdown

#### DocxFileParser

使用 Apache POI 解析 DOCX 文件。

**parse 方法调用流程：**
1. 使用 XWPFDocument 打开文件
2. 遍历提取段落文本
3. 遍历提取表格文本
4. 调用 cleanText 清洗文本
5. 构建 ParseResult 返回

**isValid 方法调用流程：**
1. 检查文件是否存在
2. 检查文件大小是否超限
3. 检查文件扩展名是否为 .docx
4. 尝试打开文件验证格式有效性

#### EncodingDetector

**detect 方法调用流程：**
1. 读取文件所有字节
2. 检查 BOM 标记
3. 尝试 UTF-8 解码
4. 尝试 GBK 解码
5. 默认返回 UTF-8

## 六、算法设计

### 6.1 文本清洗算法

```
输入：原始文本 text
输出：清洗后的文本 cleanedText

1. 统一换行符
   - 将 "\r\n" 替换为 "\n"
   - 将单独的 "\r" 替换为 "\n"

2. 去除多余空行
   - 将连续3个以上的换行符替换为2个换行符

3. 去除行首尾空白
   - 对每一行执行 trim() 操作

4. 去除首尾空白
   - 对整个文本执行 trim() 操作

返回 cleanedText
```

### 6.2 编码检测算法

```
输入：文件字节数组 bytes
输出：编码名称 encoding

1. 检查BOM标记
   - 如果前3字节为 EF BB BF，返回 "UTF-8"
   - 如果前2字节为 FF FE，返回 "UTF-16LE"
   - 如果前2字节为 FE FF，返回 "UTF-16BE"

2. 尝试UTF-8解码
   - 如果成功解码，返回 "UTF-8"

3. 尝试GBK解码
   - 如果成功解码，返回 "GBK"

4. 默认返回 "UTF-8"

返回 encoding
```

### 6.3 文本文件判断算法

```
输入：文件路径 path
输出：是否为文本文件

1. 读取文件前8KB字节

2. 遍历字节
   - 如果发现字节值为 0，返回 false（二进制文件特征）

3. 返回 true（文本文件）
```

## 七、异常处理

### 7.1 异常类定义

FileParseException 继承 RuntimeException，提供两个构造方法：
- message：异常消息
- message + cause：异常消息和原因链

### 7.2 异常场景

| 异常场景 | 异常类型 | 处理方式 |
|----------|----------|----------|
| 文件不存在 | FileParseException | 抛出异常，提示文件不存在 |
| 文件大小超限 | FileParseException | 抛出异常，提示文件过大 |
| 文件格式错误 | FileParseException | 抛出异常，提示格式不支持 |
| 文件编码错误 | FileParseException | 尝试其他编码，失败则抛出异常 |
| 文件读取失败 | IOException | 捕获并转换为FileParseException |
| 文件内容为空 | FileParseException | 抛出异常，提示文件为空 |

### 7.3 全局异常处理

GlobalExceptionHandler 通过 @RestControllerAdvice 统一处理异常：
- FileParseException -> 返回 400 状态码
- Exception -> 返回 500 状态码
